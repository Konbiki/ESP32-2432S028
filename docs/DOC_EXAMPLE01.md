# Example01_LCD : LCD表示サンプル

## サンプルについて

このサンプルでは画面四隅にそれぞれに、  
左上：青色矩形、右上：赤色矩形、左下：緑枠矩形、右下：家っぽい画像  
を描画し、中央に放射状の線を円形に描きます。  
また５秒毎に、90°画面が回転します。  

LCD制御部分は、LCD_Manager.hにコードがあります。(ヘッダオンリー)  
ESP32-2432S028専用なので、初期化等にピン番号とかの引数もありません。  



## LCDドライバIC(ILI9341)
ESP32-2432S028には320x240の液晶パネルが搭載されており、  
その表示を管理しているドライバICは ILI9341 になり、SPI経由で制御を行います。  
(少なくとも私が持っているやつは)  

このクラスのLCDドライバICは色々ありますが、  
実は基本的な描画を行うための手順はかなり似通ってます。  
各IC毎にコマンドとかはさすがに異なるのですが、  
表示させるための考え方は面白いほど似ているんです。  

なので、一つのICの使い方をマスターしれば、  
他のものもデータシートさえあれば大概ドライバソフトウェアを作れると思います。  

矩形(四角形)を表示するまでの流れは下記の様になります。  

```
GPIO初期化
　↓
SPI初期化
　↓
LCD初期化
　↓
全クリア
　↓
バックライトON
　↓　　ここまでが大体初期化処理
　↓　　ここからは描画の為の処理
描画範囲設定
　↓
画素転送
```

## GPIO初期化

ESP32-2432S028ではLCDの制御で以下のピンを出力用ピンとして設定します。

| GPIO | 名称 | 用途 |
| --- | --- | --- |
| 2 | DCピン | Data / Command<br>SPI通信で、送信する内容がコマンドなのかデータなのかを指定するピン |
| 21 | BACKLIGHTピン | バックライトをONさせるピン |

ピンとしては下記も使用されますが、  
SPI通信の初期化時に指定し、GPIOとしては使用しません。

| ピン | 名称 | 用途 |
| --- | --- | --- |
| 14 | SCLKピン | Serial Clock<br>SPI通信での、タイミング用クロック |
| 13 | MOSIピン | Master Out Slave In<br>SPI通信で、マスタ(ESP32)からスレーブ(ILI9341)
| 15 | CSピン | Chip Select<br>SPI通信で、誰(LCD)向けの通信かを決めるピン |
への送信ピン |

物によってはリセットピンがある場合もあります。その場合ハードウェアリセットが可能です。  
ESP32-2432S028ではリセットピンがつながっていないため、ソフトウェアリセットでILI9341をリセットします。  


## SPI初期化

SPI関連はフレームワークで用意されている関数を使用しています。  
(CPUメーカー製なので一番信頼できる。これまで自作しようとは思わないw)  

詳細は正式なマニュアルを見て頂きたいですが、  
spi_bus_config_t型のデータでピン配置(GPIO初期化を参照)や通信条件などを指定し  
spi_bus_initialize()でバスを初期化し、  
spi_bus_add_device()でそのバスを使用する為のハンドルを取得します。  
以降はそのハンドル経由でSPI通信を行うことになります。  


## LCD初期化

LCDへの指示はSPI経由でコマンドを送ることで行います。  
各コマンドの詳細はデータシートを見れば書いてあります。  

[Adafruit ILI9341データシート (PDF)](https://www.google.com/url?sa=i&source=web&rct=j&url=CAESbAHrOzAVLHhnnwrNsm-Q0WScysYWZe98UVGeh83fwEoG9-YBof-cpB86XvUQ_TD-6X6I188o72-SQXrI-MqKrssfG87zTo4_BHOXtZ6-L0Ba6XOhxHFcBksGB-eAQ4jEor_0mygs8i8ShXYp6w&uoh=2&ved=2ahUKEwi44-S5yMyXAxVbh68BHUnMD1kQy_kOegoIAggACAAIGxAA&opi=89978449&cd&psig=AOvVaw2bw4OFXfS9Xrtw7CXRGGH2&ust=1792722118677000)  
[MIT CBA ILI9341データシート (PDF)](https://www.google.com/url?sa=t&source=web&rct=j&url=https%3A%2F%2Facademy.cba.mit.edu%2Fclasses%2Foutput_devices%2FTFT%2FILI9341.pdf&ved=0CAAQ6vwSahcKEwiI67W6yMyXAxUAAAAAHQAAAAAQGQ&opi=89978449)  


コマンドとそのパラメタを送信する際は、
```
　DCピンをLOWにして、コマンドを送信
　DCピンをHIGHにして、データを送信
```
というの繰り返すことになります。  
(物によってはDCピンを無視して送信しても動いたりするんですけどね)  


最低限の初期化の流れは下記となります。

```
ソフトウェアリセット
　↓
スリープ解除
　↓
ピクセルフォーマット設定
　↓
メモリアクセス方法設定
　↓
画面表示開始
```
(この辺はコマンドの値やフォーマットは違いますが、ほんと他のICでも同じ感じです)


ハードウェアリセット用のピンがあれば、ハードウェアリセットを行った方が確実です。  
大抵、GPIOでリセットピンを出力設定し、  
LOW → HIGH → LOW とかすればリセットがかかります。  
(待機すする時間等はデバイスによって若干異なりますが)
ソフトリセットの場合は、コマンド Software Reset (0x01) を送信します。  

デバイスはリセット直後は大抵「スリープ状態」です。  
スリープ中にできることはほとんどないので、まずスリープを解除する必要があります。  
コマンド Sleep OUT (0x11) を送信します。  

ピクセルフォーマット設定は、デフォルトが 18bits/pixel なので、
コマンド Pixel Format Set (0x3A)で、
16bits/pixel(RGB565) (パラメタ 0x00)に変更しています。  

メモリアクセス方法の設定とは、要はどの向きで表示するかの設定です。  
LCDパネルの取り付け方法によって向きとかが変わりますので、  
場合によっては上下逆とか縦横変換(縦向き/横向きの変更)とかが必要となります。  
ESP32-2432S028ではUSBポートを下にした縦長の状態がデフォルトの向きになります。  

コマンド Memory Access Control (0x36)を送信して設定しますが、
このコマンド(MADCTL)で出来ることは左右反転/上下反転/XY軸交換などです。
これらを組み合わせて90°回転とかを実現します。

最後にコマンド Display ON (0x29)を送信して、表示を開始します。

各コマンドの送信後にそれぞれ決まったウェイトを入れる必要があったります。  
(Sleep OUTの後は120ms待機、とか。データシートを見れば書いてあります)


## 全クリア

やってみるとわかるのですが、LCDに表示していた画像とかは電源を切ってもしばらくは残ります。  
特に電源は切らずにプログラムの書き換えだけをやっている様な場合、  
前のプログラムで描画した内容がのこっていると混乱の元です。  

なので必ず最初に画面全体を黒とかで塗りつぶしましょう。
(描画範囲設定で全面指定　→　前ピクセル分黒(0x00)を送信)


## バックライトON

バックライトピンをONにしないと、画像がほとんど見えません。  
(忘れてて、なんででないかなぁ、と悩むときがあります。  
 物によっては電源ONで自動的にONになるようなボードもあります)  

というわけで、忘れずにバックライトをONしましょう。  
ESP32-2432S028の場合、GPIO-21ピンを HIGH にすることでバックライトがONになります。  



## 描画範囲設定+画素転送

ILI9341(とか同クラスのIC)で何かを描画するには、  
　描画範囲(更新する範囲)を設定　→　その範囲内の画素を順次送信  
という流れになります。  
残念ながらこのクラスのデバイスには、  
 ポリゴンを描くとかVRAM間の転送とかそういう機能はありません。  
 「ピクセル(0,0)-(29,19)を更新するよー」  
 「描画する画素情報(=色)を送るよー。赤、赤、青、青、・・・」  
って感じで描いていくことになります。  
(1pixelの変更でも、範囲指定→画素転送が必要です)

あとILI9341には取得が可能なVRAMというものはなく、  
更新する毎に色データを送ってやる必要があります。  
しかし、ESP32-2432S028には１画面分の画素情報を退避するようなメモリはないです。  
(カメラ用のモジュールとかPSRAMが載っているモジュールであれば十分に確保可能です)  
なので、半透明(今の色とのブレンドが必要)とか  
ダブルバッファリング(切り替えとかできない)とかは無理です。
